# Финальная сдача проекта на ревью (урок «Отправка проекта на ревью»)

Тип урока: `external_url_homework` (is_revisor_review_homework, saver=external_url, upload_type=url).

## Чек-лист ТЗ

1. Ветка спринта содержит актуальный код (у нас `sprint-12`).
2. `checklists/sprint-12.md` — финальный чек-лист (основная часть + доп. фича + самопроверка).
3. `README.md` — описание проекта Playlist Maker, версии Android Studio/Kotlin/SDK, шаги сборки и запуска.
4. Ветка `review` создана от базовой точки.
5. Открытый PR `sprint-12 → review` — **не мёрджить и не закрывать** до ответа ревьюера.
6. Коллаборатор `interactivetextbook` в Settings → Collaborators (может добавить только владелец репозитория).
7. Отправить ссылку на PR формой «Сдать работу».

## Чек-лист кода (урок «Финальное практическое задание»)

Актуальный текст тянется из `/api/lessons/<id>/` → `theory` → Markdown-блоки. Сводка:

- навигация в `PlaylistHost`; главный экран с 3 кнопками;
- поиск: placeholder, лупа, очистка, загрузка, LazyColumn, ошибка, mm:ss; Data/Domain/UI, `NetworkClient` + `TracksRepository`, `Storage`-эмулятор, SearchViewModel состояния;
- настройки: поделиться / письмо / соглашение, strings.xml;
- FAB → экран создания плейлиста; ModalBottomSheet → выбор плейлиста у трека;
- плейлисты: список, создание, детали (имя/описание/треки); детали трека (избранное, добавление в плейлист);
- Room (TrackEntity/PlaylistEntity/…Entity, DAO, AppDatabase), история поиска на DataStore;
- экран «Избранное»: список, заглушка обложки, удаление long-press;
- одна доп.фича по варианту вуза: удаление плейлиста / удаление трека из плейлиста / слияние плейлистов (детали — в SKILL.md).

## API отправки

```
POST https://practicum.yandex.ru/api/lessons/<lesson_id>/submit_url/
{"homework": "<PR url>", "homework_external_url": "<PR url>"}
```

`GET /api/lessons/<id>/review_history/` — история отправок.

## После ревью

- принять PR, мёрдж `review → main`;
- `git tag v11.0 && git push --tags`.

## Замечания этого прогона

- Пользователь просил репозиторий **публичным** (преподаватель без кредитов должен видеть код) — переопределяет совет урока про Private.
- Все коммиты и PR — только от имени владельца репозитория (без Devin/bot-авторства и Co-Authored-By).
- Урок «Обратная связь» (следующий) отдаёт 403, пока домашка не отправлена.

## Критично про ветку review

Ветка `review` должна указывать на самый первый коммит репозитория (init-скелет), чтобы в diff финального PR был виден ВЕСЬ код проекта. Ревьюер отклоняет PR, где видна только дельта (комментарий: «не видно всех изменений с кодом»). Не force-push review на orphan-коммит без общей истории — GitHub автозакрывает PR и не даёт его переоткрыть; в этом случае создавать новый PR и пересдавать ссылку.
